# 测试编写

被要求写测试（"补个测试"、"覆盖一下这个模块"）时按本指南执行。

## 结构（AAA）

每个用例三段式：**Arrange**（构造输入与依赖）→ **Act**（调用被测函数）→ **Assert**（断言行为而非实现）。一个用例验证一个行为——用例名就是行为的描述（`"超时 → 返回超时错误文案"`，不是 `"test1"`）。

## 先想边界，再写 happy path

高频遗漏的边界（按类型）：

- **集合/字符串**：空、单元素、超长
- **数值**：0、负数、极大值、非整数
- **时间**：跨日/跨月、时区、闰年
- **异步**：拒绝路径、超时、并发重入、取消（abort）中途
- **IO**：文件不存在、权限拒绝、部分写入后崩溃

## Mock 纪律

- mock 掉**外部世界**（网络/文件系统/时钟/第三方 SDK），不 mock **被测逻辑内部**
- 每个 mock 断言"被怎么调用"（参数与次数），防止测试静默失效
- 不要为了让测试通过而改产品代码的可观测性（加 console 之类）

## 失败信息质量

断言失败时输出的信息要能定位问题：期望值与实际值都进断言（`toBe(expected)` 自带 diff）；复杂对象断言整体相等而非逐字段拼凑。

## 红线

- 不写"永远通过"的测试（断言被注释/try 吞掉断言）
- 不依赖执行顺序或共享可变状态——每个用例自建环境
- 修 bug 先写复现测试（红）再修（绿）
