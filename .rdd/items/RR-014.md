# Raw Requirement: workspace 文件索引启动预热

## 来源
用户：项目启动时就应针对 workspace 的文件建树，实际使用时已缓存好可搜索。

## 业务目标
- 文件索引从懒缓存（首次 @ 检索才 collect）改为主动预热：进 chat（/chat 加载）即后台建树
- @ 检索时直接命中预热好的索引，无 collect 延迟

## Impact Analysis（场景 A 增量）
- 现状：/files route module-level cache（5s TTL），首次 @ 检索时同步 collect（含 gitignore 递归收集 + walk），停顿 250ms debounce 后才发 → 仍有首次延迟
- 改：抽 fileIndex 模块（collect + cache + preload）；status route（/chat 加载即调）fire-and-forget 预热；/files GET 走 getFileIndex；TTL 拉长（60s）
- 涉及：web/lib/fileIndex.ts（新）、/files route（瘦身调 fileIndex）、status route（触发预热）

## 决策（inferred 自决，non-blocking）
- 预热触发点 = status route（/chat 加载即调，早于 @ 输入）
- TTL 60s（预热后长有效，过期自然重建）
- 文件增删 staleness：60s 内可能 stale，接受（过期重建）；fs.watch 留 deferred

## 验证结果（SPEC-020）
- AC-001 getFileIndex collect + 缓存命中（同 ref）：fileIndex.test ✓
- AC-002 preload fire-and-forget 不阻塞 + 后台填缓存：fileIndex.test ✓
- AC-003 status route 触发 preload（/chat 加载即建树）：代码 ✓ + build ✓
- AC-004 /files GET 走 getFileIndex（预热后命中缓存无 collect）：files route test 3 用例 ✓
- AC-005 TTL 60s 过期重建：getFileIndex isFresh 逻辑 ✓
- web tsc 0 + 90/90；next build ✓
- 端到端：待用户起 dev 实测 @ 检索无首次延迟（预热在 /chat 加载时已建树）
