# Raw Requirement: web 从 Next.js 重构为 Vite + hono，提升架构健壮性、为桌面端打基础

## 来源
开发者自驱（架构演进）。触发：中国用户 Windows 上 `anycode web` 报 EPERM（standalone 的 pnpm `.pnpm` junction 断链），溯源发现 Next.js standalone 在 local-first 工具上系统性不适配。详见 `docs/开发问题笔记.md`「web 从 Next.js 到 Vite + hono」。

## 业务目标
1. **根除 Windows standalone junction EPERM**：Vite 静态 `dist/` 无 node_modules、无 junction，从结构上消灭该类 bug（不再靠 `nodeLinker: hoisted` 绕）。
2. **提升 web 架构健壮性**：UI（静态 SPA）与后端（独立 node server）解耦，运行时不依赖 Next standalone tracing（不再有 ripgrep 不被 trace 等坑）。
3. **为桌面端打基础**：静态 `dist/` + node sidecar 是 Electron 桌面客户端的直接载体（Electron load 静态 dist + spawn hono sidecar），对齐 opencode / hermes。

## 需求描述
用 **Vite + hono** 重构 `web/`：前端从 Next.js App Router 改为 Vite 静态 SPA（复用现有 React 组件 / Redux store / Tailwind / shadcn），后端从 Next `route.ts` 改为独立 hono node server（复用 14 个 API 路由逻辑，Web `Request`/`Response` 同构近乎 copy-paste，import `@any-code/domain`）。`@any-code/domain` 不动。launcher/installer 改为 spawn hono server + serve 静态 dist。

## 范围
- **在范围内**：`web/` 重构（Vite SPA + hono server）、14 个 API 路由迁移、`launcher.mjs`（起 hono 替 next standalone）、`install.sh/ps1`（构建/产物调整）、`useAgent` 等 SSE 客户端逻辑（应零改动或最小）。
- **不在范围内**：Electron 桌面客户端本身（本 RR 只"打基础"，桌面端是后续特性）、domain 内核改动、tui。
- **场景判定**：场景 B（整体替换）—— 删除 Next.js web，用 Vite + hono 替代。旧行为作回归基线（见 FE-019）。
