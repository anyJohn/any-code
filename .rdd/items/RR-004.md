# Raw Requirement: 流式输出（token 级）

## 来源
- README Roadmap P0-2
- 现状：`callLLM`（domain/src/llm.ts）非流式调用，整段返回后才发 `ASSISTANT` 事件；用户得等完整回复才看到内容
- 前置条件已具备：Web（`useAgent.ts`）与 TUI 已做 SSE fetch-streaming UI 侧，只差 LLM 侧 token 级流式

## 业务目标
- token 级流式输出：LLM 边生成边推送，降低首 token 延迟感，对齐主流 chat UX
- 停止语义在流式中仍闭合：`AbortSignal` 能真打断流式生成（已有 abort 穿透，需验证 stream 取消语义）

## 范围
- **domain/src/llm.ts**：`callLLM` 改为 `stream: true`，消费 `ChatCompletionChunk` 流
- **domain/src/core.ts**：`agentLoop` 处理流式响应——边累积 token 边发增量事件，流结束才把完整 assistant message push 回 messages
- **domain/src/type.ts / eventStream.ts**：事件类型设计——增量 token 事件（新增 `ASSISTANT_DELTA`？还是复用 `ASSISTANT` 带 delta 标记）
- **domain/src/session**：增量如何落盘——持久化整条 assistant message（增量累积后整条写），而非逐 token 落盘
- **web**：`useAgent` + `ChatView` 消费增量、增量渲染（markdown 边收边渲）
- **tui**：Ink `<Static>` 对增量的渲染（追加 vs 重渲最后一帧）

## 未确定事项（待逐个收敛 spec）
- **事件粒度**：token delta？句段？纯 token delta 事件量最大但最实时
- **事件类型设计**：新增 `ASSISTANT_DELTA`（累积中）+ `ASSISTANT`（整段定稿）双事件？还是 `ASSISTANT` 带 `delta`/`final` 标记？影响前端渲染与历史回放
- **历史回放一致性**：`messagesToEvents` 从持久化消息重建时，只重建 `ASSISTANT` 整段，不回放 delta（delta 是实时态，非持久态）
- **停止/abort**：流式中 abort 是否需要发一个 `STOPPED` + 截断已生成内容到一条 assistant message
- **工具调用流式**：tool_calls 在流式中如何累积（OpenAI streaming 的 tool_calls 是分片 delta，需按 index 拼装）

## 场景判断
**场景 A（增量改进）**：`callLLM` 签名形状保留（仍返回/处理 assistant message + tool_calls），内部从非流式改流式；事件流增量扩展不改既有事件语义。调用方（agentLoop）保留即增量。
