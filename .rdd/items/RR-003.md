# Raw Requirement: MCP 真协议连接（stdio/SSE）

## 来源
- README Roadmap P0-1（升为 P0 首项，原列 P1 "MCP 协议真实集成"）
- 横向对比报告（`~/Documents/Agent_Harness_Comparison_Research_20260822`）发现：anycode 与其余四款成熟 harness 最大工程落差在此——`loadMcpTools` 只把 `.anycode/mcp.json` 的 server config 当静态 `ChatCompletionTool` schema 推给 LLM，**无 stdio/SSE 真协议连接**，工具被 LLM "调用"时无 handler 可执行

## 业务目标
- 让 anycode 能真正接入 MCP 生态工具：不止告诉 LLM "有这些工具"，还要真能执行
- 消除扩展孤岛——没真 MCP，工具系统只能靠内置 8 工具 + 手写 function，生态价值为零
- 对齐成熟 harness 的工具扩展主路径（MCP 是 2026 事实标准）

## 范围
- **domain/src/mcp.ts**：`loadMcpTools` 从"静态 schema 注入"升级为"真 client 连接 + 工具 schema+handler 注册"
- **.anycode/mcp.json**：配置格式可能需扩展（command/args/env for stdio；url/headers for SSE），尽量向后兼容现有格式
- **工具系统**：MCP 工具需走 `Tool = schema + handler` 模型，纳入 `toolCall` 派发
- **连接生命周期**：spawn 时机、连接清理、与 connection-owned agent（RR-002 已实现）的交互
- domain 其他模块原则上不动，除 mcp.ts + toolCall.ts 必要改动

## 未确定事项（待逐个收敛 spec）
- **stdio vs SSE 优先级**：先做哪个？stdio 覆盖大多数本地 MCP server，SSE 覆盖远程
- **连接生命周期**：per-agent？per-session？spawn 时机（懒启动 vs 启动即连）+ 清理（agent.destroy 时 kill 子进程？）
- **Web 模式边界**：Web 服务端 spawn stdio 子进程的安全性、与单飞/连接持有的耦合
- **权限耦合**：MCP 工具是否纳入 P1 权限策略层（TOOL 事件拦截点）？还是先放行
- **配置兼容**：现有 `mcp.json` 静态 schema 格式如何过渡到真连接配置

## 场景判断
**场景 A（增量改进）**：保留 `loadMcpTools` 返回 `ChatCompletionTool[]`（或升级为 `Tool[]`）作为调用方契约（`AnyAgent.executeTask` 传 `allTools + mcpTools` 不变），内部从静态注入升级为真协议连接。调用方保留即增量，非整体替换。
