# Raw Requirement: ask_question 工具（agent 向 human 提问/求选择）

## 来源
用户 todo.md #4：「增加 ask_question 工具，当模型不确认某个事项，或者需要 human 做出选择的时候，向 human 提出问题」。要求先调研业界 + 用 rdd 开发。

## 目标
agent 在任务执行中遇到需要 human 决策/澄清/选择时，主动调一个工具把问题抛给用户、**阻塞等答案**，答案作为 tool_result 回灌 messages，agentLoop 继续推理。区别于危险命令确认（那是权限层，后续做）。

## 调研依据（源码级，已查）
三个业界主流 harness 形态完全一致：**常规 LLM 工具 + handler 阻塞 pending primitive + 答案作 tool_result**（非合成 user 消息）。
- 其一（opencode `question`）：`Effect.Deferred` 暂停；schema `{questions:[{question,header,options,multiple}]}`；UI 自动加"Type your own answer"；dismiss→tool error。
- 其二（hermes `clarify`）：`queue.Queue`/`threading.Event` 阻塞；`question`+`choices`(≤4)+`multi_select`+batch(≤5)；超时→"use best judgement" sentinel；明确"勿用于危险命令确认"。
- 其三（openclaw `ask_user`）：Gateway RPC `question.waitAnswer` 阻塞；1-3 questions、2-4 options、`multiSelect`、`timeoutSeconds`；no_answer→"proceed with best judgment"。
共性：推荐项置首+"(Recommended)"后缀（回灌前剥离）；UI 自动加 Other 自由输入；run-abort 取消 pending；agent loop 阻塞不 yield turn。

## 现状（Impact，any-code）
- `type.ts` 已有 `InteractionRequest` 接口 + `main.ts` 有 `interaction$` Subject——**定义但完全未用**（休眠 scaffold），正好复用。
- 工具系统 `Tool = {schema, handler:(args,ctx)=>Promise<string>}`；`toolCall.ts` 已发 TOOL_START/TOOL 事件 + `ctx.signal` 中断——ask handler 可 race signal：stop 时 resolve sentinel（不 reject，让 agentLoop 下轮干净 STOPPED）。
- run 路由 SSE 单向（server→client）泵事件流；答案需独立 POST 回。Next 单进程共享 module 单例 Map（dev HMR 边界可接受）。
- 无任何 ask/question 工具或交互端点。

## 范围
1. domain：`ask_question` 工具（schema + handler 阻塞等答案 race signal）+ `pendingInteractions` 注册表（module 单例 Map）+ `EventType.INTERACTION`。
2. web：`POST /api/sessions/:sid/interact` 回答端点 + 前端模态（问题 + 选项按钮 / Other 自由输入 + 多选）+ sseEvents 加 Interaction 类型。
3. 工具分组：allTools + executeTools（含 sub-agent）；readOnly 不含。
