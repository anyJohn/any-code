# Feature: Electron 桌面客户端（复用 hono sidecar + 静态 dist）

## 现状（基础，DEC-007 已就绪）
- `web/dist`（Vite 静态 SPA，0 junction）+ `server/dist/server.mjs`（hono 自包含 bundle）+ vendored rg +（win）busybox 均已就绪（RR-022 产物）。
- `@any-code/server` 是库（export `createApp`/`start`，AC-008 验证）——可被 Electron main import 内嵌跑。
- `launcher.mjs` 的 freePort 探活 + 浏览器开窗逻辑可参考（桌面换成 `BrowserWindow`）。

## 范围（Feature）
1. 新建 `desktop/` 包（Electron main + electron-builder 配置 + preload）。
2. 桌面启动流：起 hono server（嵌入 or spawn）→ `BrowserWindow` 加载 UI → 生命周期绑窗口（关窗 = stop server）。
3. 打包：electron-builder 出 Windows（NSIS exe）+ Linux（AppImage）。捆绑 `web/dist` + server + rg +（win）busybox 进 app resources（自包含，双击即用）。
4. macOS 不做（本 RR 排除）。

## Open Questions（blocking，待 Human 决策）
- **Q-021 sidecar 形态**：嵌入 Electron 主进程（`import @any-code/server`，用 Electron 自带 node 跑）vs spawn 独立 node 子进程？推荐嵌入（无独立进程、最简、复用 AC-008 库形态）。
- **Q-022 UI 加载方式**：`BrowserWindow.loadURL('http://127.0.0.1:<port>')`（server serve dist+API 同源、无 CORS、100% 复用 web 流）vs `loadFile(dist/index.html)`（离线但 file:// fetch http://localhost 撞 CORS）？推荐 loadURL（DEC-007 当初写 loadFile 是未来设想，实测 CORS 后 loadURL 更干净——此决策 refine DEC-007）。
- **Q-023 与 install 关系**：新增分发（install.sh/ps1 的 web/CLI 保留，桌面 app 另一入口）vs 取代（以后只发桌面 app）？推荐新增（双轨，用户选）。
- **Q-024 捆绑运行时**：自包含（Electron 自带 node + dist + server + rg + busybox 全打进 app，双击即用、不需 prior install）vs 依赖 `~/.anycode`（复用已装运行时，包小但依赖先装）？推荐自包含（桌面 app 的价值就是双击即用）。

## 非 blocking（SPEC 写时标 inferred，下一轮收敛）

- 桌面 app 的图标 / 启动画面 / 单实例锁。
- auto-update（electron-updater，可后续）。
- 桌面 app 是否走 `anycode update`（vs 内置 auto-updater）。
