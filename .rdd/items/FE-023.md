# Feature: 工具权限系统（策略判定 + ask 裁决 + 规则持久化 + 审计）

## Story（内联，Lite 通道）

作为 AnyCode 用户，
我希望 agent 执行危险操作（跑命令/改文件/调 MCP 工具）前按我的规则放行或询问我，
以便 agent 能放手干活，同时危险动作永远经过我的同意；
我希望"永久允许"的裁决被记住，同类操作下次不再打断我。

## 影响分析（场景 A）

| 触点 | 影响 |
|---|---|
| `domain toolCall 分发` | 执行前插入判定 seam：deny→返回拒绝结果；ask→阻塞等裁决；allow→直通。调用方（agentLoop）签名不变 |
| `domain 新权限模块` | 规则引擎（有序规则集、最后匹配生效、未命中走默认策略）+ 模式预设 |
| `domain config` | 新增 permissions 配置段（模式 + 规则，全局）；项目级规则文件（位置随 Q3 决策） |
| `domain 事件类型` | 新增权限审计事件（asked / decided），durable 入会话日志可回放 |
| `ask 交互` | 复用 pendingInteractions + Interaction 事件 + POST /interact 通道（与 ask_question 同构）；web 需裁决 UI |
| `web` | 权限裁决弹窗（区别于 ask_question 问答弹窗：展示工具名/参数摘要/风险提示 + 允许一次/永久允许/拒绝） |

## 交付物

1. **规则引擎**（domain）：`(工具名, 参数模式) → allow|ask|deny` 有序规则集，取最后匹配，未命中走当前模式的默认策略；规则来源 = 预设模式基线 + 用户持久化规则（全局 + 项目）。
2. **危险命令基线**：bash 内置危险模式库（rm -rf、sudo、磁盘/外发类）默认至少 ask——即使规则/模式放行（deny 优先于一切，含信任模式）。
3. **ask 裁决闭环**：判定为 ask → 阻塞 agent loop（超时与 abort 语义沿用 ask_question：超时按拒绝处理）→ UI 裁决 → 允许一次（会话内缓存）/ 永久允许（写规则）/ 拒绝（工具结果回传拒绝原因，模型自纠）。
4. **审计**：每次 ask/裁决/硬拦产生 durable 事件（问了什么、哪个规则/谁裁的、结果），resume 回放可见。
5. **预设模式**：至少 全部询问 / 命令写入询问+只读放行 / 全放行（信任）三档，config 一键切换。
6. **web 裁决 UI** + Settings 的 permissions 配置段（模式切换 + 已存规则列表增删）。

## 边界与非目标

- 不做沙箱/执行环境（AR-5）、不做工具元数据推导（AR-7，本版规则手工配置 + 代码内置基线）、不做 TUI/desktop 完整裁决体验（按 Q4 决策降级）。
- MCP 工具纳入同一规则引擎（按工具名匹配，无参数模式，默认 ask）——inferred，待确认。
