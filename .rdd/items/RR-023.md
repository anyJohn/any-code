# Raw Requirement: anycode 桌面端（Electron + sidecar，Win exe + Linux AppImage）

## 来源
开发者自驱。Vite+hono 重构（RR-022 / DEC-007）已"为桌面端打下基础"（静态 dist + hono sidecar 范式）。本 RR 把桌面端正式立项。

## 业务目标
1. **双击即用、无需终端**：非技术用户不用 `curl|bash` + `anycode web`，直接双击桌面 app 启动。
2. **跨平台分发**：Windows（.exe / NSIS）+ Linux（AppImage）。**macOS 本 RR 不在范围**。
3. **复用 Vite+hono 范式**：静态 dist + hono server（DEC-007），不重写 UI/API。

## 需求描述
用 Electron 包一个桌面客户端：内嵌或 spawn hono server（sidecar，复用 `@any-code/server`），Electron 窗口加载 UI；用 electron-builder 打 Windows（exe）+ Linux（AppImage）安装包。复用现有 `web/dist` + `server/dist/server.mjs` + vendored rg +（win）busybox。

## 范围
- **在范围内**：新建 `desktop/` 包（Electron main + electron-builder 配置 + preload）、Win exe + Linux AppImage 打包、捆绑运行时（dist + server + rg + busybox）、桌面启动流（起 server + 开窗）。
- **不在范围内**：macOS（本 RR 明确排除）、auto-update（可后续）、取代 install.sh/ps1（见 Q-023）。
- **场景判定**：场景 A（新特性，在已有 Vite+hono 基础上加 Electron 层）。DEC-007 已定架构范式（静态 dist + hono sidecar）。

## 未确定事项（blocking，详见 FE-020）
- sidecar 形态（嵌入主进程 vs spawn 子进程）？
- UI 加载方式（loadURL 同源 vs loadFile + CORS）？
- 与现有 install 的关系（新增分发 vs 取代）？
- 捆绑运行时策略（自包含 vs 依赖 ~/.anycode）？
