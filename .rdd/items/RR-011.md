# Raw Requirement: 思考内容落盘持久化

## 来源
用户：思考内容在切换 session 后就消失了，思考内容也需要落盘。

## 业务目标
- 思考过程（reasoning_content / THINKING 事件）随 session 持久化，切换/刷新后历史回放仍渲染 ThinkingBlock
- 推翻 SPEC-015 C-004（思考不入盘）

## Impact Analysis（场景 A 增量改进）
- 现状链：llm.ts streamCall 只回调 onThinkingDelta 不累积 → 返回 message 无 reasoning → core.ts 发 THINKING 事件仅入内存 eventStream → main.ts onMessage=appendMessage 落盘标准 ChatMessage（无 reasoning）→ /history 返回无 reasoning 的 messages → web messagesToEvents 不产 Thinking → 回放后 TurnItem.thinking 恒 undefined → ThinkingBlock 不渲染（B-007）
- 关键约束：OpenAI 标准 ChatCompletionMessage 无 reasoning 字段（completions.d.ts L804-837），须自定义扩展；assistant message 若挂非标准字段直接喂 callLLM 会被部分 provider 400，需剥离点
- 涉及：domain/src/llm.ts、core.ts、main.ts、session/*；web/lib/sseEvents.ts、history route、chat page
- 既有 SPEC：SPEC-015（C-004 需 superseded，B-007 需补"回放也渲染"）

## 范围
- domain：累积 reasoning + 挂载落盘 + LLM 入口剥离
- web：history shape 暴露 reasoning + messagesToEvents 重建 Thinking 事件

## 未定（见 Open Questions）
- 落盘方案：message 内联 / 独立 entry kind / _meta sidecar
- 实时 THINKING 事件是否仍不入盘（仅靠落盘字段回放重建）
- 字段命名

## 决策（Human 决）
- 落盘方案 = _meta sidecar（DEC-055）
- LLM 入口剥离点在 callLLM（DEC-056）
- 实时 THINKING delta 不入盘，回放靠 _meta.reasoning 重建（DEC-057）

## 验证结果（SPEC-017）
- AC-001 streamCall 累积 reasoning → message._meta.reasoning：domain llm.test ✓
- AC-002 callLLM 剥离 _meta（payload.messages 不含）：domain llm.test ✓
- AC-003 messagesToEvents 重建 Thinking（_meta.reasoning → Thinking 事件）：web renderItems.test ✓
- AC-005 向后兼容（无 _meta 不产 Thinking）：web renderItems.test ✓
- AC-006 真 LLM run：glm-5.2 思考型任务，84 个 THINKING 实时 delta（471 字符）累积落盘为 _meta.reasoning（471 字符）✓；回放重建由 AC-003 单测覆盖
- domain tsc 0 + 49/49；web tsc 0 + 81/81
