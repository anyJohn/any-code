# RR-028: browser_use 工具增强

browser_use（CDP 单工具：navigate/content/eval）在真实页面上痛点密集，用户实测列了 6 项（#16-21）。
本 RR 收敛为一期可落地的改动集；"要不要换 agent 操作范式（视觉定位/aria 快照）"作为独立开放问题。

## 用户原始反馈（逐条）

1. eval 的 fetch 被 zone.js 污染（页面注入脚本干扰 eval 环境）
2. async 表达式序列化丢失——返回 Promise 时拿到的是空壳，应 await 后再序列化
3. content 无截断，爆上下文——需要 maxChars 上限 + 支持 selector 指定区域
4. navigate 超时误判——SPA 异步渲染被当成加载失败；应区分网络 load 与 SPA 路由，或超时后仍返回页面状态
5. 无 cookie 操作能力
6. 无法指定 target 页签，只能操作第一个

## 开放问题（blocking）

1. **操作范式**：继续 CDP eval 自研，还是引入 Playwright 库（locator/aria 快照）做底层？"大模型对哪个工具做过专门优化"——Playwright 的 aria 快照是当前 agent 操作浏览器的事实标准。
2. **范围**：一期只修 2/3/4（小修）+ 5/6（增强），还是连 1 一起（换执行沙箱）？

## 初步判断（待用户决策后立 SPEC）

- 2/3/4 是小修，风险低，先做
- 5（cookie）/6（多页签）需要扩工具参数面（action=cookie / targetId）
- 1 的根治 = 换 Playwright runtime，工作量大，倾向单独立项（browser v2.1 与 desktop 内嵌 CDP 合并考虑）
