# Feature: MCP 真协议连接

## 现状（Impact）
- `domain/src/mcp.ts` 的 `loadMcpTools` 只读 `.anycode/mcp.json`，把 server config 当静态 `ChatCompletionTool` schema 推给 LLM——**无 stdio/SSE 真协议连接**，工具被 LLM "调用"时 `toolCall` 找不到 handler（按 name 派发失败 → `[Error] Function not found`）
- 与四款成熟 harness 最大工程落差；没真 MCP，anycode 工具系统只能靠内置 8 工具 + 手写 function，生态价值为零
- 现有 `toolCall`（tools/toolCall.ts）已按 `Tool = schema + handler` 派发，MCP 工具只需注册成 `Tool`（schema 来自 server、handler 转发协议调用）即可接入，**派发侧已就绪**

## Stories（Lite 内联，不拆 US）

### US-A MCP client 真连接 ✅ 待实现
`loadMcpTools` 升级：对每个配置的 server 建真连接（stdio spawn 子进程 / SSE HTTP），list_tools 拿工具 schema，包装成 `Tool`（handler = 经连接 call_tool 转发）。

### US-B 配置格式扩展 ✅ 待实现
`.anycode/mcp.json` 支持 stdio（command/args/env）与 SSE（url/headers）两种 server 描述；向后兼容现有格式（旧静态 schema 标 deprecated 或映射）。

### US-C 连接生命周期 ✅ 待实现
连接与 agent 绑定：懒启动（首次 list_tools/call_tool 才连）或启动即连；`agent.destroy()` 时清理（kill stdio 子进程 / 关 SSE 连接），与 RR-002 连接持有 agent 一致。

### US-D Web 模式安全边界 ✅ 待实现
Web 服务端 spawn stdio 子进程——限制（不暴露公网、开发服务器仅 127.0.0.1 已有）、与单飞/连接持有耦合（MCP 子进程随 agent destroy 一起 kill）。

## Open Questions（全已决策 → DEC-016..019，见 SPEC-006）
