# Raw Requirement: 完善 any-code Web 端 Session 管理 / 用户体验 / Memory 功能

## 来源
用户提的三个 Epic：
1. Web 端丰富 Session 管理功能（删除、编辑等）
2. Web 端提升用户体验（loading 状态、圆角卡片式布局）
3. 完善 Memory 功能（LLM 介入保证记忆高质量，仅必要时才记项目记忆，实现 workspace 与全局划分）

## 业务目标
让 web 端从「能跑」升级到「好用 + 可维护」：
- session 可删除/编辑，不再只能新建和切换
- 加载/失败/空三态清晰，不再混淆；布局卡片化、圆角统一
- memory 不再无脑全记（当前连"打个招呼"都进 memory.md），由 LLM 把关质量，并区分项目级与全局级记忆

## 范围
- **web 层**：session 管理 UI + route、loading/卡片/圆角、错误提示
- **domain 层**：memory 子系统（saveMemory/loadMemory 介入 LLM + 新增全局层）
- domain 其他模块（agentLoop、tools、session store 等）原则上不动，除 memory 必要改动

## 三个 Epic → Feature 映射
- Epic 1 → FE-001 Session 管理（删除/编辑）
- Epic 2 → FE-002 用户体验（loading/卡片/圆角）
- Epic 3 → FE-003 Memory 高质量化（LLM 介入 + 分层）

## 未确定事项（详见 OPEN-QUESTIONS）
- "编辑 session" 指重命名标题还是编辑消息（后者需 store 改造）
- Memory LLM 介入模式（逐条判断 / 摘要蒸馏 / memory 工具主动调用）
- workspace/全局 memory 数据模型与写入边界
- 删除软/硬、确认流程、loading 与卡片化的具体范围
