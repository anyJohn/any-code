# Raw Requirement: anycode 配置体系 + Web 交互增强

## 来源
用户提的 5 个 Epic：
1. anycode 支持配置文件，支持多 provider，流式输出和非流式
2. anycode Web 页面支持查看和修改配置，并进行配置热更新
3. anycode Web 页面支持 "/" 指令
4. anycode Web 页面支持 "@" 引用文件
5. anycode Web 对话页面支持上下文余量用量显示、当前模型、skill 与 mcp 的 status 监控展示

## 业务目标
让 anycode 从"单一 .env 配置 + 基础聊天"升级到"可配置多 provider + Web 可视配置/热更新 + 富交互（slash/@file）+ 可观测状态面板"：
- 配置层：告别单一 OPENAI_* 环境变量，支持命名多 provider + 流式开关
- Web 交互：配置可在线查看/改/热更新；输入框支持 slash 指令与 @file 引用（对齐主流 chat UX）
- 可观测：对话页实时看上下文余量、当前模型、已加载 skill 数、MCP server 连接状态

## 范围
- **domain 层**：配置文件加载（多 provider + 流式开关）；暴露状态（上下文用量、当前 model、skill 数、MCP 连接状态）供 web 读
- **web 层**：配置面板（查看/改/热更新）、slash 指令、@file 引用、状态/用量监控面板
- **tui**：不在本轮范围（聚焦 web 体验）；配置文件 domain 侧改动 tui 自动受益

## 五个 Epic → Feature 映射
- Epic 1 → FE-008 配置文件 + 多 provider + 流式开关（domain 基础，其余依赖）
- Epic 2 → FE-009 Web 配置面板 + 热更新
- Epic 3 → FE-010 Web slash 指令
- Epic 4 → FE-011 Web @file 引用
- Epic 5 → FE-012 Web 状态/用量监控面板

## 依赖关系（影响收敛顺序）
- FE-008 是基础：FE-009 编辑的配置、FE-012 读的 model/provider/skill/mcp 状态都依赖 FE-008 定的配置形态与 domain 暴露面
- FE-010 / FE-011 相对独立（web 输入框交互）
- 建议收敛顺序：FE-008 → FE-009 / FE-012 → FE-010 / FE-011
