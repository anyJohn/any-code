# Raw Requirement: contextWindow 自动探测 + 取最小

## 来源
用户：能否真实获得模型的最大支持上下文长度？做一个小特性。设计细节：探测到上下文窗口但用户也在 config 配了，取两者最小（避免超出真实上下文窗口），且支持用户配更小窗口。

## 业务目标
- contextWindow 不再纯靠手填 128000：启动时探测 provider 的 GET /models 是否返回真实 context_window
- 探测值与用户配置值取 min（用户配更小则用更小，防超真实窗口）
- 探测不到 → 内置模型表回退 → 用户配置 → 128000

## Impact Analysis（场景 A 增量）
- 现状：config.normalize contextWindow 缺省 128000；core.ts Usage 事件 data.contextWindow = ctx.llm?.contextWindow ?? 128000；status 端点读 provider.contextWindow；settings 表单无 contextWindow 字段（用户只能改 yaml）
- 实测：dashscope /models 仅返回 {id,object,created,owned_by}，无 context 字段 → 探测对 dashscope 静默回退；OpenAI 官方新版 API 返回 context_window → 探测生效
- 涉及：domain/config.ts（contextWindow 改 optional + resolve/detect）、main.ts initConfig（async 探测）、core.ts、status route、web settings 表单 + /api/config 保 contextWindow

## 决策（Human 决）
- 探测值与用户配置取 min（DEC-063）
- contextWindow 改 optional（undefined=未配，避免缺省 128000 误截断探测的大值）（DEC-064）
- 内置模型表仅含确信值（OpenAI 常见模型），probe/user 优先（DEC-065）

## 验证结果（SPEC-019）
- AC-001 resolveContextWindow 取 min 各组合：domain config.test ✓（detected+user→min；仅 detected；仅 user；全无→128000；模型表截断；用户更小）
- AC-002 detectContextWindow：domain config.detect.test ✓（context_window/context_length 取值；无字段→undefined；抛错→undefined；缓存命中不重复网络；apiKey 空不调）
- AC-003 initConfig 探测+resolve 写回：真 run ✓（agent 启动正常，contextWindow resolved）
- AC-004 status 端点 resolveContextWindow（不探测）：代码 ✓ + build ✓
- AC-006 settings 表单 contextWindow 输入（空=auto）+ 保存保留：toConfigShape/fromResponse ✓ + build ✓
- AC-007 真 run：dashscope /models 无 context 字段 → detect undefined → 回退 128000 ✓
- domain tsc 0 + 62/62；web tsc 0 + 84/84；next build ✓
- 探测值路径（OpenAI 官方返回 context_window）由 AC-002 单测覆盖；本机 dashscope 不支持探测，真 run 验回退路径
