# Feature: 上下文压缩（compact 指令 + 75% 自动）

## 现状（Impact）
- 无 compact / 摘要 / token 估算代码。agentLoop 已有真实 usage.prompt_tokens 信号 + resolved contextWindow。
- sessionStore append-only，无整体替换 messages 的能力。
- web 无 slash 命令框架。

## Stories（Lite 内联）
- US-A token 估算：`estimateTokens(messages, lastUsage?)`——有真实 usage 用 prompt_tokens，否则 chars/4 over JSON.stringify(messages) 兜底。
- US-B compactMessages 核心算法：messages=[system,...rest] → 保护 system[0] → rest 切 head(摘要)/tail(保留原文)，切割点保留 tool_call/tool_result 配对（不在 assistant tool_call 与其 tool result 之间切）→ 序列化 head 成文本（tool 输出截断 ~2000 字符）→ LLM 摘要调用（同 provider、`tools:[]`、max_tokens ~4096、结构化 Markdown 模板）→ head 换成一条 summary 消息。
- US-C 摘要消息存储：role + 落盘方式（见 Open Questions Q-1/Q-2 决策）。
- US-D 自动压缩：agentLoop 迭代边界（callLLM 前）查 lastUsage.prompt_tokens >= 75% * contextWindow → compactMessages → 原地替换 messages → 发 COMPACT 事件 → 继续循环。
- US-E 手动 /compact：`AnyAgent.compact(focus?)` 公共方法 → compactMessages（focus 注入摘要 prompt）→ 替换 session + 落盘 → 发 COMPACT 事件。
- US-F session replaceMessages：`SessionService.replaceMessages(key, messages)` 原子重写 JSONL（写临时文件 + rename）。
- US-G web slash 命令：chat 输入识别 `/compact[ <focus>]` → POST `/api/sessions/:sid/compact` → 成功插 System 事件"已压缩上下文"→ 不走 /run。
- US-H 事件 + 渲染：EventType.COMPACT；web MessageList 渲染压缩事件（显示压缩前后 token 数 / focus）。
- US-I 摘要 prompt：结构化 Markdown 模板（目标/关键细节/已完成/进行中/阻塞/下一步/相关文件）+ "REFERENCE ONLY" handoff 前缀；有旧摘要则走 update 模式（合并，新对话覆盖旧）。

## Open Questions（blocking，待 Human 决 → DEC-095.. 落 SPEC-025）
- Q-1（blocking）压缩后原始历史是否保留（可恢复）？ → A) 直接 rewrite（简，丢原始，摘要即记录） / B) 另存全量 archive（可恢复，复杂）。推荐 A（MVP 简单；archive 作 follow-up）。
- Q-2（blocking）摘要消息的 role？ → A) `user` + "REFERENCE ONLY" 前缀（OpenAI 兼容、不改 schema，最简） / B) 专门 `system` 角色中插 / C) 新增自定义 role（需改 type + 部分 provider 拒）。推荐 A。
- Q-3（blocking）尾部保留策略？ → A) 按"最后 N 条消息"、N≈6、配对感知（调研的某业界主流 harness 同路，简） / B) token 预算 ~8-20K（另两路同路，更省）。推荐 A（简、够用；token 预算 follow-up）。
- Q-4（非 blocking）manual `/compact [focus]` 支持 focus 文本？ → 推荐 支持（三工具都有、成本低）。
- Q-5（非 blocking）auto 阈值源 = 真实 usage.prompt_tokens @ 75% contextWindow？ → 推荐 是（信号现成、最准；chars/4 仅首迭代兜底，首迭代不会触 75%）。
- Q-6（非 blocking）slash 命令框架是否做成可扩展？ → 推荐 仅识别 /compact 前缀（最简，留扩展余地）。
- Q-7（非 blocking）摘要调用用同 provider/model？ → 推荐 是（不引第二条配置；tools 禁用、max_tokens 4096）。
