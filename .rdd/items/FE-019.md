# Feature: web 重构为 Vite SPA + hono node server

## 现状（Impact baseline / 回归基线，场景 B）
- web = Next.js 15 App Router；4 页面/layout 全 `"use client"`；14 个 API 路由（`app/api/*/route.ts`，Web `Request`/`Response` 形状，import `@any-code/domain`）。
- 运行：`next build` → `.next/standalone/web/server.js`，launcher 起 standalone server（HOSTNAME=127.0.0.1）+ vendor rg + 注入 `ANYCODE_RG_PATH`。
- **旧行为回归基线**（迁移后须保持）：`anycode web` 起 127.0.0.1 本地服务、浏览器自动开、SSE 流式 `/run`、14 个 API 端点语义不变、`useAgent` fetch-stream 正常、rg 可用。

## 范围（Feature）
1. **前端 Vite SPA**：`web/` 改 Vite + React，复用 components/hooks/store/Tailwind/shadcn；换 `next/navigation`→react-router、`next/link`→router Link、`next/image`→img、删 `metadata`。构建产静态 `dist/`。
2. **后端 hono node server**：14 路由从 `route.ts` 迁 hono（`NextResponse.json`→`c.json`/`Response.json`，SSE `Response(ReadableStream)` 原样），import `@any-code/domain` 不变。
3. **运行时/构建**：launcher 起 hono server + serve 静态 dist（替 next standalone）；install.sh/ps1 构建链调整（`vite build` + hono server，去 `next build` / standalone post-process）。
4. domain 不动；tui 不动。

## Open Questions（blocking，待 Human 决策）
- **Q-014 迁移策略**：big-bang 全量替换 Next vs 增量（Next + Vite 并存逐步迁）？推荐 big-bang（web 是单 interface、调用方清晰、并存双跑成本高）。
- **Q-015 包结构**：新建 `@any-code/server` 包（web SPA + server 分离）vs 单 `@any-code/web` 包内 `server/` subdir？推荐新建 server 包（domain 复用 + 桌面端可独立 spawn server 包，对齐"打基础"）。
- **Q-016 静态 dist serve**：hono 一体 serve（一个进程管 dist + API）vs 分离（hono 只 API + 独立静态 / Electron loadFile）？推荐 hono 一体（web 模式最简；桌面端再切 Electron loadFile + hono sidecar，两者不冲突）。
- **Q-017 前端路由**：react-router v7 vs TanStack Router vs 其它？推荐 react-router v7（生态成熟、与现有 next/navigation 用法最近）。
