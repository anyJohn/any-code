# Raw Requirement: 文件系统全面优化 + 引入 ripgrep

## 来源
用户：对 anycode 文件系统全面优化，引入 rg，对标业界主流 agent harness。
Web 端 3 个具体问题：
1. @ 引用文件时列表出现后不断调用 /files 接口致卡顿
2. @ 但未添加文件时应弹列表展示 workspace 文件，而非无反应
3. 输入文字后再 @，@ 前应有空格

## Impact Analysis（场景 A 增量 + B 局部替换）
- web @file 补全（useFileReference / fileIndex / /files route）：3 bug + 改 rg --files 数据源
- domain glob/grep 工具：纯 JS（glob npm + 自写 walkDir + 逐文件 readFile 逐行 regex）→ 改 ripgrep（对标业界主流做法）
- 调研依据：业界主流 agent harness 普遍用 ripgrep 做文件枚举/内容搜索（系统 rg + fallback 路线、打包二进制纯 argv spawn 路线均有）

## 根因
1. useFileReference effect 依赖 atMatch（每次 render 新数组引用）→ setFileItems 触发 render → effect 重跑 → 循环
2. !fileToken early return → @ 单独无列表
3. atMatch 正则不要求 @ 前空格 → "文字@" 误触发

## 范围
- 引入 ripgrep（依赖形式待决）
- web：fileIndex 改 rg --files + 修 3 个交互 bug
- domain：glob/grep 工具改 rg（尊重 .gitignore）

## 未定（见 Open Questions）
- rg 依赖形式（@vscode/ripgrep 打包 vs 系统 rg vs fallback）
- domain glob/grep 是否一并改 rg（全面 vs 仅 web）
- 问题3 @ 前空格（规则要求 vs 自动插空格）
- 预热策略（保留 status route 预热 vs rg 够快不预热）

## 决策（Human 决）
- rg 依赖 = @vscode/ripgrep 打包二进制（DEC-071）
- 范围 = domain + web 全改（DEC-隐含）
- 问题3 = 规则要求 @ 前空格/行首，不自动插（DEC-073）
- 不预热不缓存，每次实时 rg（DEC-074）
