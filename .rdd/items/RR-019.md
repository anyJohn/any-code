# Raw Requirement: 上下文压缩（compact 指令 + 75% 自动压缩）

## 来源
用户 todo.md #1：「feature：支持 compact 指令和自动上下文压缩（75%时）」。要求先调研业界主流 harness 的 compact 方式，再用 rdd 技能完成。

## 目标
长会话逼近上下文窗口时，把旧消息总结成一条摘要 + 保留近期尾部原文，避免 prompt 溢出、控制成本。两条触发路径：
1. 手动 `/compact [focus]` 指令——用户主动压缩，可选聚焦主题。
2. 自动压缩——上下文用量达 75% 时在迭代边界触发。

## 调研依据（源码级，已查）
三个业界主流 harness 形态高度一致：**总结旧消息成一条 summary + 保留近期尾部原文 + 保护 system prompt + 切割边界保留 tool_call/tool_result 配对**。都用 chars/4 启发式（非真 tokenizer），都优先用 provider 真实 usage 回填。
- 其一：阈值 **75%**（命中本需求）；`protect_first_n=3 / protect_last_n=6`；chars/4；迭代式 summary（有旧摘要则 update）；"REFERENCE ONLY" handoff 前缀（摘要只作背景、勿续作旧任务、最新用户消息优先）。
- 其二：绝对 token 预留（非百分比）+ 溢出重试兜底；keep_recent ~8K tokens；专门 `Compaction` 消息类型；结构化 Markdown 模板（Objective/Important Details/Work State/Next Move/Relevant Files）；压缩调用 `tools:[]` 禁用工具、max_tokens 4096。
- 其三：近上限 + 溢出重试；keepRecent=20K；`compactionSummary` 角色；safeguard 质量审计 + 纠正重试；CJK 感知 chars/4。

## 现状（Impact，any-code）
- `agentLoop`（core.ts）已捕获 `msg.usage.prompt_tokens` 并发 USAGE 事件；`ctx.llm.contextWindow` 已 resolved（initConfig 探测）。**真实 token 信号现成**，自动压缩 75% 阈值无需 tokenizer。
- `session.messages` 是 `ChatMessage[]`（OpenAI param），system 在 [0]、每 task 重建不入盘；其余 append-only 落盘（JSONL）。**无 rewrite/replace API**——压缩要整体替换 messages，需补原子重写。
- web `submit(task)` POST `/run`，**无 slash 命令解析**；run 路由 single-flight、终态/断连即 destroy。
- 无任何 compact / 摘要 / token 估算代码。

## 范围
1. domain：token 估算（真实 usage 优先 + chars/4 fallback）、`compactMessages()`（切分+序列化+摘要 LLM 调用+重组）、auto-compact 在 agentLoop 迭代边界、manual `compact()` 公共方法、COMPACT 事件。
2. session：`replaceMessages()` 原子重写 JSONL。
3. web：`/compact` API 路由 + chat 输入 slash 命令识别（`/compact [focus]`）+ COMPACT 事件渲染。
