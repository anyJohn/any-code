# Feature: provider 多模型 + /model + /provider 指令

## 现状（Impact）
- config provider 仅单一 `model: string`，无多模型
- `/model <name>`（FE-010）切的是 **provider**（default），不是模型——语义错位
- 无 `/provider` 指令

## Stories（Lite 内联）
- US-A config schema：provider `model` → `models: [{id, name?}]` + `defaultModel`（当前模型 id）；向后兼容旧 `model:`
- US-B callLLM：用 `provider.defaultModel` 作 API model 参数
- US-C `/model` 指令：`/model` 显当前模型 + 列 provider 的模型；`/model <id>` 切 defaultModel（当前 provider 内）
- US-D `/provider` 指令：`/provider` 显当前；`/provider <name>` 切 default provider
- US-E /settings：编辑 provider 的 models 列表（id+name）+ defaultModel
- US-F status：显当前模型（id/name）

## Open Questions（全已决策 → DEC-047..050，见 SPEC-014）
- Q-1 表示 → models:[{id,name?}] + defaultModel (DEC-047)
- Q-2 /model 范围 → 当前 provider 内 (DEC-048)
- Q-3 /model <arg> → 按 id (DEC-049)
- Q-4 旧 model → 不兼容（未发布无用户）(DEC-050)

## 实现记录
- domain：
  - `config.ts`：LlmProvider `model` → `models:[{id,name?}]` + `defaultModel`；normalize + load/save 校验（models 非空 + defaultModel 在 models）；自动建默认（models:[{id:gpt-4o,name:GPT-4o}] + defaultModel:gpt-4o）；不兼容旧 model
  - `llm.ts`：callLLM 用 `provider.defaultModel` 作 API model
- web：
  - `/api/config` PATCH 扩展：`{default? 切 provider, modelId? 切当前 provider 模型}`（服务端 load+改+save 保留 apiKey）
  - `/api/workspaces/[pk]/status`：返 defaultModel + modelName
  - `ChatView`：/model 改切模型（无参显当前+列 models，/model <id> PATCH modelId）；新增 /provider（无参显当前，/provider <name> PATCH default）；BUILTIN_COMMANDS 加 provider；StatusBar 显 modelName
  - `/settings`：ProviderForm 改 models 列表（id+name 增删）+ defaultModel 下拉；toConfigShape/fromResponse 适配
- `config.example.yaml`：新 schema（models+defaultModel）
- 测试：config.test 改 models+defaultModel（AC-001/002/007）；llm.test PROVIDER 改 models
- 验证：domain tsc 0 + 37/37 + build；web tsc 干净 + 54/54
- deferred：/model//provider 补全排序、model 级 streaming/contextWindow 覆盖
