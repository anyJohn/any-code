# Feature: Memory 高质量化（LLM 介入 + 分层）

## 现状（Impact）
- **无脑全记**：`main.ts:234` `saveMemory(task, result, workspace)` 无条件写，连"打个招呼"/"你是什么模型"都进 memory.md（实例 `.anycode/memory.md` 600 行可见）
- **零 LLM 参与**：`memory.ts:25` 纯模板拼接 `**Task:** ${task}\n\n**Result:** ${result}`，无判断 / 无摘要 / 无判重 / 无分类
- **只有项目级，无全局**：memory 落 `<rootPath>/.anycode/memory.md`；全局 `~/.anycode/` 仅存 `workspaces.json` 注册表，不放 memory
- **介入点单一**：`saveMemory`（`memory.ts:17`）唯一写入口，`loadMemory`（`:39`）唯一读入口，调用点仅 `main.ts:234`（写）/ `main.ts:252`（读），blast radius 极小
- **读取滑动窗口 1000 字符**（`memory.ts:46-54`），条目多了从末尾截断丢历史
- **格式半结构化**：`## ISO时间戳` + Task + Result + `---`，无 importance/tag/source 层级
- memory.ts 顶注已列 TODO（RAG / 压缩蒸馏 / 分层 / 检索工具），现状空白

## Stories

### US-007 LLM 介入「必要时才记」
在 saveMemory 内或调用前加 LLM 判断 / 摘要，避免闲聊/重复/stop 入库。
- 待决策（Q-010，blocking）：介入模式 = 逐条 LLM 判断 / LLM 摘要蒸馏后记 / memory 工具让 LLM 主动调用 / 组合
- 代价：前两种每任务多一次 LLM 调用 + 延迟；第三种改 agentLoop 注入工具
- 不动 agentLoop 主体，只在 saveMemory 或其调用边界改

### US-008 workspace / 全局记忆分层
新增全局记忆层（如 `~/.anycode/memory.md` 或 `~/.anycode/memory/global.md`），workspace 保持现状；改 load/save 签名区分层级。
- 待决策（Q-011，blocking）：全局放哪、谁可写全局（跨 workspace 共享偏好 vs 仅项目）
- 参考 `REGISTRY_DIR`（`workspace.ts:29`）加全局目录常量；`workspaceConfigDir`（`:138`）目前只产项目路径

### US-009 记忆读取策略改进（条件性，待 Q-012）
窗口截断 → 按重要性取 / RAG 检索 / 全量。
- 若不引入结构化 importance，则 US-009 退化为"调大窗口"小改；若引入则需改 memory 格式 + loadMemory 解析

## Open Questions（本 Feature）
- Q-010 LLM 介入模式（blocking，决定架构与 cost）
- Q-011 workspace/全局 数据模型与写入边界（blocking）
- Q-012 记忆是否结构化（importance/tag）+ 读取策略
- Q-013 记忆格式保持 markdown 还是改 JSONL/结构化
