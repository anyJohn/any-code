# Feature: Web @file 引用文件

## 现状（Impact）
- Web 输入框无法引用文件，用户得手敲路径让 agent read；无 @ 触发的文件选择

## Stories（Lite 内联）
- US-A 触发：输入框 "@" → 弹出文件选择（workspace 内文件 autocomplete）
- US-B 选择：模糊匹配文件路径，选中插入为 @path chip
- US-C 注入：引用的文件如何进 context（全文注入 vs 只路径让 agent read）待决
- US-D 多引用：支持多个 @file，提交时一并处理

## Open Questions（全已决策 → DEC-041..044，见 SPEC-011）
- Q-1 注入 → **路径注入**（agent read 读取，agentic，支持所有格式）(DEC-041 修订)
- Q-2 发现 → 模糊匹配 + **尊重 .gitignore**（不排除二进制）(DEC-042 修订)
- Q-3 路径 → 相对 workspace root (DEC-043)
- Q-4 chip → 可删 + 文件名（tooltip 全路径）(DEC-044)

## 实现记录
- web：
  - `app/api/workspaces/[projectKey]/files/route.ts`：GET ?q= 递归扫 workspace 文件，模糊匹配，限 20，**尊重 .gitignore**（用 `ignore` 包读各级 .gitignore），跳 node_modules/.git/.next/dist/.cache/.anycode；不排除二进制（agent read 支持所有格式）
  - `components/ChatView.tsx`：`@` 触发（非 / 模式）→ 文件 popover（↑↓+Tab/Enter 选中）；选中插 `@path` chip（文件名+tooltip 全路径，× 删/backspace 删）；提交时各 chip **路径**注入 user 消息（`<text>\n\nFiles: rel/path1, rel/path2`），agent 用 read 工具读取（agentic，无 web 内容拉取）
  - 与 `/` 指令共存（/ 开头走 FE-010 指令模式，否则 @ popover）
  - 装依赖 `ignore`（gitignore 解析）
  - 删旧方案残留的 /file 内容路由（路径注入无需内容拉取）
- 验证：web tsc 干净 + 10/10 文件 54/54 测试 0 失败
- deferred：.gitignore 多级/否定模式深度、文件发现缓存、多 chip 顺序
