# Raw Requirement: 端到端安装（Win+Linux 安装脚本 + anycode web）

## 来源
用户讨论：any-code 已达 MVP，要给**非技术用户**用。约束：web 是打磨门面（TUI 不完善、不作入口）；终端用户机器**不能假设有 node/npm/pnpm/git**；v1 不做客户端（Electron 作后续大特性）。决定靠两个安装脚本做"最简端到端安装"。

## 目标
非技术用户一行命令装好 → 运行 `anycode web` 起本地 web agent，开箱即用。支持 Windows + Linux。

## 范围
1. `build/` 目录：Linux install.sh、Windows install.ps1+install.bat、launcher.sh/launcher.bat、versions.env、README。
2. 一行安装命令拉仓库 zip（codeload，不依赖 git）→ 私有 provision node（nodejs.org tarball 到 ~/.anycode/runtime/node，corepack 激活 pnpm）→ pnpm install + pnpm --filter @any-code/web build → 注册 anycode 到 PATH → 提示 anycode web。
3. `anycode web` 启动器：next start（仅 127.0.0.1）+ 开浏览器 + 前台（Ctrl+C 杀）。本地构建 node_modules 已在，不用 standalone。
4. Windows agent bash 一并做：内嵌 PortableGit（非 MinGit，需 bash.exe+coreutils）保持 bash 全平台统一；bash.ts 从 spawn(cmd,{shell:true}) 改显式 spawn(binary,["-c",cmd])，按平台解析 shell（unix /bin/sh、win bash.exe via ANYCODE_GIT_BASH_PATH），cwd MSYS 翻译 C:\Users→/c/Users。
5. 配套小改：domain/package.json 加 @vscode/ripgrep-win32-x64 optionalDep；根 package.json 加 packageManager（corepack 锁 pnpm）。

## 调研依据（源码级，见会话）
- 调研的 4 个业界主流 harness 在 Windows 全走 native（不走 WSL）。
- bash 处理两路：pwsh-native（prompt 分叉）vs PortableGit（bash 统一）。any-code 单代码库+bash skills → 选 PortableGit（业界主流 harness 同路）。
- 私有 provision node = 业界主流 harness 的私有 node 目录同模式。

## 决策（Human 决，全已定）
- 不发 npm；本地构建模式；运行 next start（不 standalone）。
- Win+Linux；macOS/客户端/签名后续。
- Windows agent bash 纳入本次（非后续）。

## 前置风险
web 只验过 `next dev`，**prod 模式（next build + next start）端到端未验**——SSE/domain transpile/serverActions 若在 prod 有坑，整个安装流是断的。SPEC AC-004 列为前置验证。
