# Feature: Web 端 Session 管理（删除 / 编辑）

## 现状（Impact）
- domain 已有能力：`SessionService.remove`（`sessionService.ts:58-60`，硬删 fs.unlink）、`SessionService.setTitle`（`:69-71`，追加 meta 行实现重命名，不改旧行）
- domain **无**「编辑已发送消息」能力：`SessionStore` 接口只有 append/load/list/remove，append-only jsonl
- web **完全无** session 级 DELETE/PATCH route；`AppSidebar.tsx:135-155` session 按钮只有 onClick 切换，无删除/编辑入口
- 主键关系：`sessionId` 是磁盘与列表真正主键；`agentId` 只是内存路由 key。新 route 应走 `/api/workspaces/[projectKey]/sessions/[sessionId]`，与 agentPool 解耦

## Stories

### US-001 删除 session
用户在侧栏 session 上触发删除 → 二次确认 → 调 `SessionService.remove` → 列表移除。
- 待决策：软删（可恢复）/ 硬删（现状）；确认弹窗形式；删当前活动 session 时 agent 失效如何处理
- 依赖：domain remove 已就绪，仅需 web route + UI

### US-002 重命名 session
用户在侧栏 session 上 inline 编辑标题 → 调 `SessionService.setTitle` → 列表刷新。
- domain setTitle 已就绪，仅需 web route + inline edit UI

### US-003 ~~编辑 session 内消息~~（已撤销，DEC-003）
编辑已发送消息本轮不立项。append-only store 改造成本大、收益边际，留待将来独立 FE。

- Q-005 列表刷新策略（重新拉取 / 本地更新 map）
